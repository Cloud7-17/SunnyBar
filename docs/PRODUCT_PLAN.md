> 文档版本：v0.1（2026-10-27）
> 项目状态：规划阶段
> 项目类型：Windows 桌面常驻工具
> 目标读者：项目发起者、开发者、Codex 等编程代理

## 0. 项目摘要（Project Brief）

**Sunny Bar** 是一个在 Windows 任务栏上方显示的细长、半透明时间轴，用来把一天可视化。时间轴范围为**当日凌晨 04:00 至次日凌晨 04:00**；背景颜色根据日出、日落在日间和夜间之间渐变；太阳/月亮图标标记日出/日落；用户自定义的小图标标记当前时刻；另外允许设置“开始工作”“准备睡觉”等每日固定时间分割点。

最初版本不是传统日历，也不是待办事项软件。它首先应做到：**打开电脑就能看见一天走到了哪里，同时不妨碍其他工作。**

后续版本在同一时间轴上叠加日程区间、高亮当前任务和任务提示。

### 0.1 一句话产品定义

> 一条贴近 Windows 任务栏、跟随太阳与时间流动的每日进度条。

### 0.2 用户故事

- 作为用户，我想在不打开专门应用窗口的情况下，迅速看出今天已经过去多少时间。
- 作为用户，我想知道今天的日出、日落分别位于时间轴的哪里，直观感受白昼与黑夜。
- 作为用户，我想自定义当前位置图标，以及睡眠、工作等每日关键时间标记。
- 作为用户，我希望程序常驻，但不遮挡任务栏、不打断其他软件操作。
- （V2）作为用户，我想在时间轴上看到接下来要做的事情，并知道自己当前处于哪个计划时段。

## 2. 视觉和交互要求

### 2.1 参考结构（示意，不代表最终像素稿）

```text
            ☀ 日出                         ☾ 日落
             │                              │          ★ 当前
04:00   ─────┼───── 08 ─── 12 ─── 16 ─────┼── 20 ─────●── 00 ─── 04:00
         深夜 → 清晨/白天颜色渐变 → 傍晚/深夜颜色渐变
                    ↑ 开始工作                           ↑ 睡眠（示例）
──────────────────────── Windows 任务栏 ─────────────────────────
```

> 示例位置、日出日落时间和图标仅用于说明；实际显示由地点、日期和设置决定。

### 2.2 悬浮窗

| 项目 | V0.1 默认值/规则 | 可配置时机 |
|---|---|---|
| 显示位置 | **主显示器**的任务栏上方，屏幕水平居中 | V0.2 可调偏移和长度 |
| 时间轴宽度 | **铺满主屏工作区宽度（100%）**，不留左右空白 | V0.2 |
| 视觉长条高度 | **16 DIP**；图标与实线合计 **32 DIP**，下方不显示时间刻度 | V0.2 |
| 下边距 | **0 DIP**，可见条的下沿直接贴住任务栏上沿 | V0.2 |
| 层级 | 无边框、透明背景、正常使用时悬浮在普通窗口之上 | V0.2 可关闭常驻最前 |
| 鼠标行为 | **默认整体穿透**；停留约半秒后显示不抢焦点、可穿透的信息浮层，移开后隐藏 | V2 可增加交互模式 |
| 管理入口 | Windows 系统托盘图标：显示/隐藏、设置、退出 | V0.2 完善 |

重要：**不是修改 Windows 系统任务栏，也不是把内容注入 Explorer 进程。** Sunny Bar 是一个独立的轻量悬浮窗口，视觉上贴近任务栏。

2026-10-27 按用户截图修订：以上全宽、贴边和无悬浮刻度为当前默认。详细预览仍可显示刻度；悬浮条悬停信息按后续用户要求精简为当前时间、下一标记和剩余时间；详细信息保留在预览窗口。

2026-10-27 日程反馈修订：新建按钮立即创建并选中默认日程，编辑通过“保存修改”提交；日程色带占顶部 50%，外观设置可调 10%–100%。悬停在原信息上增加当前日程起止、结束倒计时，以及下一日程和开始倒计时。

2026-10-28 交互修订：可见色条改为接收双击，打开统一日程/标记编辑窗口，单击不激活，空白区域与信息浮层继续穿透；不使用全局鼠标钩子。编辑窗口采用左侧导航，顶部为日程、每日标记，下方为低频设置。日程默认色带改为顶部 40%（保留已保存比例），真实起止点增加实心方形/空心圆形标志，裁剪边界不标为真实起止。

2026-10-28 当前日程交互补充：日程真实起止竖线贯穿整个时间条高度，覆盖色带仍按原比例显示；日程与每日标记页各提供“清除全部”，确认后立即保存，取消或写入失败保留数据，清除标记不提交其他设置草稿。

2026-10-28 日程易用性补充：增加“上课”预设，提供 08:00–09:35、09:50–11:25、09:50–12:15、13:30–15:05、15:20–16:55、19:20–20:55、19:20–21:45 七项，选日期后单次创建。新日程自动避免使用已有日程的颜色；精简设置说明，保留必要字段、时区、状态和确认。

### 2.3 日夜视觉

- 设定两组基本色：`Night = #28324B`，`Day = #F6BD77`（建议色值，可按设计稿调整）。
- 日出前以 Night 为主；日出后向 Day 过渡；日落前后向 Night 过渡。
- 过渡窗口默认日出和日落**前后各 30 分钟**，使用平滑渐变，禁止生硬颜色断层。
- 日出位置显示**太阳图标**，日落位置显示**月亮图标**；图标应采用自带矢量资源，避免因电脑字体不同而丢失。
- 没有日出或日落的特殊日期（如高纬地区极昼/极夜）不能崩溃：显示可解释的单一日夜底色，不强行虚构图标。
- 日出日落为**天文计算估算值**，不是天气预报或实时天气数据。

2026-10-28 深夜试验：增加本地 00:00 星形标记，将夜晚与深夜区分。00:00 到下一次日出的黑夜区域保留原夜色并叠加稀疏细闪星点；按 04:00 展示窗口裁剪，处理 DST、日出早于 04:00、极昼极夜及无地点回退，隐藏或关闭时停止动画，尊重系统动画开关。

2026-10-28 星点反馈调整：提高深夜星点密度、半径、峰值亮度和柔光，缩短明暗周期，让细闪更容易观察；继续保持仅深夜显示和隐藏停机，不更改系统动画设置。

### 2.4 当前时间指针

- 在时间轴上显示当前时间位置，随系统时间连续推进。
- 默认用小圆点或自带矢量图标；用户可以选择内置图标、输入一个 Emoji，或从本地选择 PNG 图片。
- PNG 可以复制到应用数据目录，避免源文件移动后导致图标丢失；路径无效时回退到默认圆点。
- 当前指针必须比渐变背景、固定分割点更醒目，但不能太大。
- 指针更新周期默认 **30 秒**，并在应用启动、系统唤醒、日期变化和配置变化时立即刷新。

### 2.5 自定义固定分割点（MVP 范围）

每个固定分割点包含 `id`、`label`、`time (HH:mm)`、`color`、`enabled`；例如：

```json
[
  { "id": "work-start", "label": "开始工作", "time": "09:00", "color": "#5AA9E6", "enabled": true },
  { "id": "sleep", "label": "准备睡觉", "time": "00:30", "color": "#AF8FDD", "enabled": true }
]
```

- 显示为细竖线、微小图形或简短文字；与日出日落标记、当前指针区分。
- 每天重复，**不等同于 V2 中具有起止时刻的日程事件**。
- 标签重叠时优先保证标记点正确，可以隐藏部分文字，而不是让排版失控。
- 不需要在悬浮条上直接编辑；通过设置窗口维护即可。小时、分钟分别支持输入与下拉选择；颜色使用可见色板与调色盘。提供一键添加预设：上班 10:00、午饭 12:00、晚饭 18:00、睡觉 23:00，不自动写入用户配置。

## 3. 时间模型（实现时必须统一）

这是项目中最容易产生偏差的部分，需先设计、先做单元测试。

### 3.1 “今天”的定义

Sunny Bar 的“一个工作日/展示日”不是 00:00 到 24:00，而是 **04:00 → 次日 04:00**。

- 若当前系统本地时间 `>= 04:00`，展示日起点为**今天 04:00**。
- 若当前系统本地时间 `< 04:00`，展示日起点为**昨天 04:00**。
- 展示日终点是展示日起点的**下一自然日 04:00**。
- 04:00 时新展示日开始，当前位置回到长条最左端。

### 3.2 时间映射公式

正常的 24 小时展示日：

```text
start = 本展示日 04:00
end   = 下一自然日 04:00
progress = clamp((now - start) / (end - start), 0, 1)
x = barLeft + progress * barWidth
```

日出/日落和用户分割点都必须经过**同一个映射函数**，不能分别用不同换算方法。

跨日分割点规则：例如 `00:30` 要归属展示日的**第二个日历日**，而不是绘制到 04:00 之前。对于每天重复的 HH:mm 标记，时间小于 04:00 的标记应向后推一天。

### 3.3 示例（无夏令时转换的普通日）

| 时刻 | 期望位置 |
|---|---:|
| 04:00 | 0% |
| 06:00（日出示例） | 8.33% |
| 09:00（工作示例） | 20.83% |
| 16:00 | 50.00% |
| 18:00（日落示例） | 58.33% |
| 次日 00:00 | 83.33% |
| 次日 00:30（睡眠示例） | 85.42% |
| 次日 03:59 | 接近 100% |
| 次日 04:00 | 开始新的展示日，回到 0% |

### 3.4 时区和夏令时（DST）

- 使用**操作系统时区**解释当前时间；不要把 UTC 简单当成本地时间。
- 内部使用具备时区偏移的 `DateTimeOffset` 或 UTC 瞬时值计算进度，保证指针随真实时间单调前进。
- 对发生 DST 的日期，04:00 到次日 04:00 的实际时长可能为 **23 或 25 小时**。以**实际经过的时间**分配长条位置；该日不是强行平均的 1440 分钟。
- 正常日的四小时刻度可以等距；DST 特殊日的刻度位置应按同一时间轴计算，而非硬编码等距。
- 在自动时间回拨的重复小时中，时间标签可重复；首版至少保证不会崩溃、指针不会倒退。

### 3.5 日出日落计算

- 按用户 2026-10-27 的明确要求，首次使用默认采用北京预设，可切换上海、广州或手动输入经纬度；移除特罗姆瑟预设。既有地点（包括明确未选）保留，地点信息**保存在本地**。
- V0.1/V0.2 不获取浏览器定位，也不需要持续联网。
- 采用可离线运行的成熟太阳位置计算方法（例如参照 Jean Meeus/NOAA 公布的天文计算思路）；引入第三方库前确认其许可证、维护情况和计算准确性。
- 以地点、日期、**系统本地时区**计算当前展示窗口涉及的太阳事件，返回带明确时间偏移的时间点。
- 04:00→次日04:00 跨两个日历日：需要检查相关日期的事件，并仅绘制落在展示窗口内的事件；不要假设一定有且只有一组日出/日落。
- 用户修改地点/系统时区/日期时重新计算；失败时可显示默认中性色时间条并提示设置，而不是使应用不可用。

> 首版以“用户当前所在地点与 PC 系统时区一致”为前提。**不支持选择一个异地城市同时显示该城市独立时区**；该功能可后续增加。

## 4. 技术方案与模块划分

### 4.1 推荐技术栈

- 语言：**C#**。
- UI：**WPF (XAML)**。
- 框架：**.NET 10 LTS**，目标 Windows 11，Windows 10 尽力兼容并实机验证。
- 测试：**xUnit**（主要测试不依赖 GUI 的时间逻辑）。
- 持久化：`System.Text.Json` + `%LocalAppData%\SunnyBar\settings.json`。
- 日出日落：封装独立计算器接口（可自研可靠实现或采用经过确认的离线库）。
- 桌面窗口：WPF 无边框透明 Window，必要时使用少量 Win32 P/Invoke。
- 托盘：`System.Windows.Forms.NotifyIcon`。
- 构建发布：`dotnet publish` 自包含的 `win-x64`，GitHub Releases；安装包可选择 Inno Setup 或 WiX。
- 源码管理：Git + GitHub + GitHub Actions（Windows 构建）。

选择 WPF 是因为最重要的需求是**系统级悬浮窗口和位置控制**，而不是跨平台网页组件。没有理由在首版强行采用复杂的浏览器 + 原生桥接方案。

### 4.2 核心模块

| 模块 | 职责 | 关键输入/输出 |
|---|---|---|
| `DisplayDayService` | 判断当前展示日、起止时刻、DST | `now` → `DisplayDayWindow` |
| `TimeAxisMapper` | 把任意时刻映射到 `[0,1]` | 时刻 + 展示日 → 归一化坐标 |
| `SolarEventService` | 计算日出日落/日夜状态 | 地点 + 日期 + 时区 → 太阳事件 |
| `TimelineViewModel` | 合成渲染所需状态 | 展示日、太阳事件、分割点、当前时刻 |
| `TimelineControl` | 绘制渐变、刻度、图标、竖线 | ViewModel → WPF 图形 |
| `BarWindow` | 悬浮条窗口生命周期 | 透明、置顶、鼠标穿透 |
| `WindowPlacementService` | 获取主屏工作区并定位 | `rcWork` + DPI → 窗口坐标 |
| `SettingsService` | 本地读写设置和校验 | JSON ↔ 配置模型 |
| `TrayService` | 系统托盘控制入口 | 显示/隐藏/设置/退出 |

建议坚持**纯计算逻辑与 WPF UI 分离**，使 Codex 可先通过单元测试验证时间行为，再处理 Windows 界面细节。

### 4.3 Windows 桌面行为约定

1. 悬浮窗 `WindowStyle=None`、`AllowsTransparency=true`、`ShowInTaskbar=false`，不在 Alt+Tab 等切换列表中制造干扰。
2. 首版通过主显示器 `GetMonitorInfo(...).rcWork` 获取未被任务栏占据的工作区，定位在其底部上方；要正确处理像素/DIP 及 DPI 缩放。
3. 任务栏高度或工作区尺寸变化、显示器分辨率变化时重新定位。
4. 默认鼠标穿透；Win32 扩展窗口样式的具体选择必须实测，避免“视觉透明但仍抢走点击”。托盘菜单是主要交互入口。
5. 不注册系统 AppBar、不预留整个屏幕区域、不注入 Explorer、不要求管理员权限。
6. 若出现全屏游戏/演示遮挡，首版至少能从托盘一键隐藏；自动检测全屏属于增强功能。
7. **单实例运行**，避免误启动多个悬浮条；程序退出时释放托盘图标、事件订阅和其他资源。

## 5. 设置与数据结构

### 5.1 V0.2 设置页建议分区

- **位置**：预设城市、手动经纬度；显示本地时区说明。
- **时间轴**：宽度比例、纵向偏移、透明度、刻度显示开关。
- **视觉**：日夜主题色、当前指针内置图标/Emoji/PNG。
- **分割点**：添加/编辑/删除/启停每日固定时间标记。
- **运行**：显示/隐藏、开机自启动开关、退出应用。

注意：开机自启动采用显式 opt-in，**默认关闭**，不做静默安装或系统设置改动。

## 9. 代码质量和开发代理约定

1. **先验收单个里程碑，再进入下一个。** 不要一次性生成一个难以调试的大工程。
2. 时间计算使用依赖注入的 `IClock` 或可替换的时钟抽象；单元测试禁止直接依赖真实系统当前时间。
3. 测试中应注入固定的太阳事件数据以验证画图位置；不要让 UI 测试被实时天文算法结果绑死。
4. 所有时间的换算应集中在核心服务，不允许在 XAML 事件回调里散落 `+4/-4` 等魔法数。
5. 提供可解释的错误信息；配置文件损坏时备份旧文件并恢复默认配置，不静默丢失用户数据。
6. 不增加无必要的后台服务、管理员权限、远程联网、账号系统、遥测、自动更新器。
7. 第三方软件包必须注明用途和许可证；首版依赖越少越好。
8. Codex 在每一阶段输出：修改的文件、实现功能、执行的命令、测试结果、遗留问题、下一步建议。
9. **开发环境如果不是 Windows，不得声称已验证实际悬浮、鼠标穿透、多 DPI 或托盘运行。** 可以先完成纯逻辑与静态构建，并将 Windows 手测事项列明。
10. 不要为了实现 V2 提前重构全部架构；只需保持核心数据层可扩展。
